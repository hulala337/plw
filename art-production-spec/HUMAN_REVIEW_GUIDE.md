# Pelican Workbench 人工审核指南

本文件定义美术资产从候选到 APPROVED 的人工审核流程。人工审核是最终审美门禁，AI/自动 QA 不得替代。

## 一、去哪里审核

每个生成资产都应先保存为候选图，并在仓库中保留候选文件和审核记录。人工审核时，打开当前资产的候选图，实际查看画面；不要只根据 AI 的文字描述决定批准。

审核对象至少包括：
- 角色身份与 B01 风格锚点是否一致
- 动作/表情是否符合当前 asset brief
- 构图、比例、透视、光影、细节和完成度
- 是否出现 AI 乱码、无意义文字、异常肢体或随机元素
- 是否与 Pelican Workbench 的整体美术方向一致
- 技术 QA 是否通过（尺寸、格式、透明背景/裁切等，以 Manifest 为准）

## 二、怎样批准

人工审核不是在聊天里说一句“看起来不错”就算完成。必须明确指定“哪一个候选”被选中，并把结论写回仓库。

推荐流程：
1. AI 生成一个或多个候选。
2. AI 完成技术 QA 和视觉 QA，并把候选列出来。
3. AI 停在 HUMAN REVIEW REQUIRED，不得自行 APPROVED。
4. 人打开候选图进行实际审核。
5. 人明确给出：APPROVE + 候选文件名（或明确的候选 ID）。
6. AI 将人工结论写入对应 review 记录，并把该资产 STATE/Manifest 状态更新为 APPROVED。
7. commit + push。
8. 下一次接力从最新 STATE 继续。

## 三、如果不满意

明确给出 REWORK，并说明需要修改的方向。AI 应保留原候选和审核记录，生成新版本，不得覆盖历史候选后假装通过。

## 四、最简单的人工指令

审核通过时可以直接告诉执行 AI：

APPROVE：选择候选 [文件名/候选ID]，作为该资产正式版本。请写入人工审核记录，将当前资产更新为 APPROVED，并 commit + push；不要生成下一个资产，除非 STATE 已明确允许。

需要返工时可以说：

REWORK：当前候选不通过。原因：[具体问题]。请保留原候选和审核记录，按当前资产 brief 重新生成版本，不要推进到下一个资产。

## 五、重要原则

- AI PASS_TO_HUMAN ≠ 人工 APPROVED。
- 人工 APPROVED 必须能追溯到具体候选文件/版本。
- APPROVED 后仍需按项目流程进行 INTEGRATING/FROZEN。
- P0/P1 资产必须人工审核。
- 换账号、换平台、换电脑后，审核状态以 GitHub 中的 STATE 和 review 记录为准。
- 不要在仓库保存 API Key、密码、Token、Cookie 等凭据。
